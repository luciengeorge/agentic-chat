# Follow a request through Grafana

👨‍💼 When a Kestrel employee says "the assistant is slow", you need to know which service was slow. A trace tells you.

## Terms

- A **trace** is the record of one request as it crosses services.
- A **span** is one piece of work inside a trace, like "Envoy checked the token" or "the api read the database". Spans nest: a parent span waits on its children.
- **OpenTelemetry** is the standard our services use to send spans. **Tempo** stores them, and **Grafana** draws them.

## Do this

1. 🐨 With the stack running, run `uv run ex smoke` once. It sends a request through the gateway and a row through the outbox, so there is something to look at.
2. 🐨 Open Grafana at http://localhost:3001, go to **Explore**, and pick the **Tempo** data source.
3. 🐨 Search for recent traces and open one from the api. Find the spans for the gateway, the api, and the database call.
4. 🐨 Now find a trace for the hello workflow. Notice that it starts in the relay, not the api: the api only wrote a row, and the relay picked it up later.

🦉 Each span records its start time and its duration. The widest bar is where the time went. When a trace has a gap with no span in it, the time went somewhere nobody measured, and that's worth a span of its own.

💯 Look at the logs panel for the same trace id. Our logs carry the trace id, so you can jump from a slow span to what the service printed at that moment.
