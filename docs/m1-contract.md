# M1 contract (reference RAG)

The shared agreements for M1's lanes. `PLAN.md` says why; `docs/m0-contract.md` still holds for everything M0 set up (env via `acEnv()`, ports, the `#learn` slots, `ex`, the quality bar), and its "Backlog for M1" is part of this milestone's scope where a lane touches that code. If a lane has to break this contract, it says so in its report instead of silently diverging.

**M1 is done when** a question asked in the app is answered with citations, ACLs and tenancy enforced by the database, the Heron memo never reaches `leo.martin`, and the golden set clears its bar. M1 runs in waves of at most two agents.

| Wave | Lanes |
|---|---|
| 1 | A. Ingestion (this file, in detail). B. Parse + chunk (this file, in detail) |
| 2 | C. Retrieval (embeddings, HNSW, pg_search BM25, RRF, rerank, ACL filter, audit). D. Answer + app (model client, generation, citations, auth boundary, chat UI) |
| 3 | Integration + golden set |

Decisions Lucien made for M1: OpenAI only for now (Cohere rerank stays behind `rerank()` with a fake until a key exists); RLS enforced in M1 with a non-owner role and `FORCE`; 1536-dimension embeddings; `gpt-6-luna` with medium reasoning, effort always explicit.

## The rule for code layout

Everything a later exercise will ask the learner to write lives in `src/core/<area>/<module>.ts` and is imported as `#learn/<area>/<module>` by the app, workflows and tests. Glue (routes, workflows, DB writes, wiring) lives outside `src/core`. A module in `src/core` takes its dependencies as arguments (a fetch, a clock, a db handle) so tests can drive it without the stack.

Lane A alone uses the live stack (Docker, :3000, :8100); lane B tests offline and runs docling on :5001 only for its comparison, telling lane A first. Neither lane stops Docker or OrbStack. No nested subagents.

## Shared types (lane B writes these first, then tells lane A)

```ts
export type Block =
  | { kind: "heading"; level: number; text: string }
  | { kind: "text"; text: string }
  | { kind: "table"; markdown: string; rows: number }
export interface Page { number: number; blocks: Block[]; method: "text-layer" | "ocr"; ocrConfidence?: number }
export interface ParsedDocument { mimeType: string; pages: Page[] | null; blocks: Block[] } // pages null for md/docx
export type Rasterise = (pdf: Uint8Array, pageNumber: number) => Promise<Uint8Array> // PNG
export interface ParseDeps { rasterise: Rasterise; ocr: (png: Uint8Array) => Promise<{ text: string; confidence: number }> }
export function parse(bytes: Uint8Array, mimeType: string, deps: ParseDeps): Promise<ParsedDocument>

// src/core/chunk/types.ts
export interface Chunk { ordinal: number; text: string; pageStart: number | null; pageEnd: number | null; section: string | null; tokenCount: number }
export function chunk(doc: ParsedDocument, options?: { targetTokens?: number; overlapTokens?: number }): Chunk[]
```

## Lane B: parse + chunk

- PDFs: text layer per page with `unpdf` (or `pdfjs-dist`); a page whose text layer is empty or below a threshold is rasterised and OCR'd with `tesseract.js` (word confidences kept; the page's mean goes in `ocrConfidence`). Rasterising uses a native canvas, so it is a dependency the caller passes in (`ParseDeps.rasterise`): Workflow steps can't load native modules on Vercel (workflow #1003), so lane A calls it through a server route. DOCX with `mammoth` (headings, paragraphs, tables). Markdown passes through as blocks.
- Tables become markdown with their header row; a table that runs across pages stays one block per page, header repeated.
- Chunking: token counts with `gpt-tokenizer` (the `o200k_base` encoding), default 512 tokens with 64 overlap. Never split a table row, never split inside an identifier or a word, prefer heading boundaries, carry the nearest heading as `section`, and set pages for PDFs only (both or neither, as the schema's CHECK demands).
- Tests run over the committed corpus (`fixtures/corpus/build`): every one of the 46 documents parses; scans and handwriting go through OCR; the pdf_mixed contract has text pages and OCR'd pages; every KPC-, KP-, SKU and person-name token in a source appears whole in some chunk (the M0b lesson); no chunk exceeds the target by more than one row or sentence; pages are right for a sample of known facts (filing pages 130, 328, 845, 883, 2417, 2468, 2861).
- docling: a `docling` service in `compose.yaml` (`docling-serve-cpu`, pinned tag, :5001, a `profiles: [docling]` so `ex up` doesn't pull 4.4 GB by default) and `scripts/parse-compare.ts`, which runs both parsers over a few trap documents and prints where they differ. It is a comparison tool, not a dependency of ingestion.

## Lane A: ingestion

- **RLS enforced.** A migration creates a non-owner login role `ac_app` (no BYPASSRLS) granted what the app needs, and `FORCE ROW LEVEL SECURITY` on every tenant table. App code reaches tenant data only through `withTenant(tenantId, fn)`, which runs `fn` in a transaction after `SET LOCAL app.tenant_id`. Cross-tenant work (the outbox relay, directory sync across tenants, seeding, migrations) uses the owner role through an explicitly named `systemDb`. `DATABASE_URL` becomes the `ac_app` URL; `DATABASE_ADMIN_URL` the owner's. Tests prove a forgotten `withTenant` sees nothing and a cross-tenant write is refused. The DB pool is a process-wide singleton (`globalThis[Symbol.for("agentic-chat.db")]`) because step code and the Vite graph load modules twice in dev (M0 backlog).
- **Connector** (`src/core/connectors/graph.ts`): a client for fake-workspace's Graph-style API with full crawl (follows `nextLink`), backoff on 429 honouring `Retry-After`, delta (`token=latest` before a crawl, then apply changes; 410 `resyncRequired` restarts with a crawl), dedupe by item id (keyset paging can return an item twice), deletes and moves. Its state lives in `sync_state`.
- **Directory sync** (`src/core/directory/`): users (`accountEnabled: false` makes `principals.enabled = false`), groups, direct members into `group_members`, and `group_closure` computed from them (no self rows, depth from 1); checked against `/transitiveMembers` in a test. Membership and `enabled` changes don't advance `acl_version_seq` (M0 decision).
- **ACL stamping** (`src/core/acl/`): an item's effective permissions (own plus inherited) become `document_acl` rows (`allow`), mapped from Graph ids to `principals`; every change draws a new `acl_version` from the sequence. Postgres stays the only decision point.
- **Storage.** Raw bytes go in a new tenant table `document_blobs(tenant_id, sha256, bytes bytea, size, mime_type)`, content-addressed; `documents.storage_key` is the sha256.
- **Workflows.** A sync workflow (crawl or delta for one tenant) writes `documents` rows and an `outbox` row per document to ingest, in one transaction. The relay (a Nitro plugin loop in dev) claims outbox rows with `FOR UPDATE SKIP LOCKED` and starts an ingest workflow per document, whose first step claims the row by id (the relay can deliver twice). Ingest: download, store the blob, parse (rasterise through a server route), chunk, write `chunks` (no embeddings yet; wave 2 fills them), set `status = ready`. The 3,000-page filing fans out to child runs by page range. Steps use `RetryableError` for 429s and network errors and `FatalError` for bad input, with explicit retry limits.
- **Webhooks.** `POST /api/webhooks/workspace` answers the validation handshake and turns a notification into a delta sync for that tenant through the outbox. It checks `clientState`.
- **Tests and live proof.** Unit tests with fake-workspace in-process and throwaway databases. Live: from an empty `ac`, `pnpm ex up`, `pnpm dev`, `pnpm fake-workspace`, then a full sync of both tenants: all 46 documents `ready` with chunks and ACLs; a rename, a move, a delete and a sharing change made through fake-workspace's control API arrive by webhook and apply; removing `leo.martin` from `/Kestrel/Finance/AP` in the directory removes his closure rows. A new `ex smoke` check, "ingestion", covers counts and one ACL fact (the Heron memo's `document_acl` holds `/Kestrel/Exec` only).

## Settled during the build

(Lanes add what they decide here.)

**Lane B (parse + chunk)**

- **Where the functions live.** A `.ts` file can't declare a function without a body. So `types.ts` holds the types plus `Parse` and `ChunkDocument` function types, and the code lives in `#learn/parse/parse` (`parse`, `pdfPageCount`, the `PDF`, `DOCX` and `MARKDOWN` mime constants, `UnsupportedDocumentError`) and `#learn/chunk/chunk` (`chunk`, `DEFAULT_TARGET_TOKENS`, `DEFAULT_OVERLAP_TOKENS`). Below them sit `parse/{pdf,layout,tables,docx,markdown}.ts` and `chunk/tokens.ts`.
- **Page ranges, for the filing's fan-out.** `parse` takes an optional fourth argument, `{ pages: { from, to } }`: 1-based, inclusive, PDFs only. Page numbers stay those of the whole document. A range on md or docx throws `UnsupportedDocumentError`; so does an unknown mime type, which ingestion treats as a `FatalError`. A range outside the document throws `RangeError`. `pdfPageCount(bytes)` gives the count without parsing.
- **Blocks.** A table's `rows` counts the rows under its header. Its `markdown` always starts with the header and the `| --- |` line. List items and bullets become text blocks that start with `- ` (or `1. `). In PDFs a heading is found by font size: 16pt or more is level 1, 13pt level 2, 11.5pt level 3. The bottom 6% of a page (the running footer, "Page 2 of 7") is dropped. A split table keeps the header that the renderer repeats on each page.
- **OCR.** A PDF page with fewer than 20 visible characters in its text layer is rasterised and OCR'd. OCR'd pages give text blocks only, one per paragraph, with no headings. `ocrConfidence` is the mean word confidence, from 0 to 100, to one decimal place. The defaults are `rasterisePage` in `src/lib/parse/rasterise.server.ts` (unpdf with @napi-rs/canvas, at 2x) and `ocrPng` in `src/lib/parse/ocr.ts`. The second uses tesseract.js with its LSTM engine and the English model from `@tesseract.js-data/eng`, and it reuses one worker; `terminateOcr()` stops it. Nothing is fetched, and nothing is cached in the working directory.
- **Chunks.** A heading always starts a new chunk, so no chunk spans two sections, and overlap never crosses a heading. A section longer than the target splits between sentences (or between words, for a sentence longer than the target). It carries whole trailing sentences or rows, up to `overlapTokens`, into the next chunk. A chunk that holds table rows starts that table with its header. The chunk text is markdown, with headings as `#` lines. `section` is the nearest heading's text, not a path. Ordinals start at 0 on each call, so a fan-out offsets them. At the defaults the filing parses in about 3 s and gives 5,274 chunks.
- **Identifiers in tests.** The "whole in some chunk" check covers every document except scans and handwriting. It also skips the scanned signature page of the pdf_mixed contract, since OCR misreads characters there by design.
- **docling** is pinned to `quay.io/docling-project/docling-serve-cpu:v1.35.0`, and `scripts/parse-compare.ts` uses its async API (`/v1/convert/file/async`, then poll, then result) with JSON output.

**Lane A (ingestion)**

- **Two roles, two URLs.** The `app_role` migration creates `ac_app` (NOLOGIN, no BYPASSRLS) if it's missing, grants it DML on every table and USAGE plus SELECT on the sequences (with default privileges for later tables), and forces RLS on every tenant table. A role belongs to the whole server, so a migration can't know its password: `pnpm db:migrate` now runs `src/db/migrate-main.ts`, which applies the migrations as `DATABASE_ADMIN_URL` and then gives `ac_app` LOGIN with the password in `DATABASE_URL` (`src/db/app-role.ts`). `drizzle.config.ts` reads `DATABASE_ADMIN_URL`. The tests' global setup does the same once per run, with `DATABASE_URL`'s password when it names `ac_app`, else the dev `ac_app`; CI sets both URLs. Drizzle can't declare FORCE, so the drift test forces RLS on the schema-built database before it compares.
- **Pools.** `src/db/pool.ts` keeps one pool per URL on `globalThis[Symbol.for("agentic-chat.db")]`, made on first use: `appDb()` (`DATABASE_URL`) and `systemDb()` (`DATABASE_ADMIN_URL`). `src/db/client.ts` still exports `db` (the app role) for better-auth. `withTenant(tenantId, fn)` and `withTenantOn(db, tenantId, fn)` are in `src/db/tenant.ts`; a tenant id that isn't a uuid throws.
- **What runs as which role.** Request code, workflow steps, the webhook and directory sync run on `ac_app` inside `withTenant`: each sync handles one tenant, so directory sync never crosses tenants. The seed stays on `ac_app` too, since it writes only better-auth's tables, which carry no RLS. `systemDb()` is used by the relay, by `pnpm sync` to list tenants, and by `ex smoke` check 1 (the probe table needs CREATE). `ex smoke`'s targets gain `adminDatabaseUrl` (from `DATABASE_ADMIN_URL`).
- **Principal ids are the directory's ids.** `principals.id = external_id` (Entra ids are uuids; directory sync refuses one that isn't). A user's principal id is then the better-auth user id and the world's `userId`, so wave 2 can join a viewer to `document_acl` with no lookup. A principal the directory stops listing is disabled, never deleted.
- **Connector.** `src/core/connectors/graph.ts` holds no state; the delta link lives in `sync_state.delta_token`. It retries 429 and 503 itself (`Retry-After`, else exponential) before it throws; a `GraphRequestError` is `retryable` for 429, 5xx and no answer, and steps turn that into `RetryableError` with the same `retryAfter`, anything else into `FatalError`. The crawl yields files only. A delta entry has no path, so a changed file is read again (`GET items/{id}`) and a changed folder is crawled again, which re-paths the files a folder rename moved. The drive-to-`documents` logic is `src/core/connectors/drive-sync.ts` (`fullSync`, `deltaSync`). New content (a new sha256) bumps `documents.version` and queues an ingest; a rename, move or sharing change doesn't. A delete removes the chunks and the ACL rows (with a new `acl_version`) and marks the document `deleted`; the blob stays.
- **ACLs fail closed.** Read and write grants both become `allow`. A grant to an id with no principal yet is left out and reported (`unknownPrincipals`), and the sync runs directory sync first so that's rare. A stamp with no change draws no version. A document nobody may read still gets a version, so `acl_version > 0` means "stamped".
- **Sync runs.** `syncWorkflow(tenantId, outboxId | null, "full" | "delta", { subscribe? })`: claim, directory, drive, subscription. The drive step runs in one transaction under a tenant advisory lock (`pg_advisory_xact_lock` on `sync:<tenant>`), HTTP included, and writes `documents`, ACLs, `sync_state` and the ingest rows together. A 410 turns a delta into a full sync. Every sync syncs the directory, since Graph sends no notification for a membership change. Every sync renews the subscription: fake-workspace forgets subscriptions when it restarts or resets, and the renewal's 404 is how we find out (the live proof caught this). Subscriptions last 3 days; only a sha256 of the clientState is kept (`sync_state.client_state_hash`, beside `subscription_id` and `subscription_expires_at`).
- **The site and its token.** A tenant's site is its organization slug. Its token is `WORKSPACE_TOKEN_<SLUG>` when set, else, outside prod, fake-workspace's dev token.
- **Outbox and relay** (`src/db/outbox.ts`). New columns `claimed_by` (the run id) and `claimed_at`. Partition keys are `sync:<tenant>` and `document:<id>`. A relay pass locks a batch with SKIP LOCKED, then takes each partition with `pg_try_advisory_xact_lock` and skips it if an older pending row of that partition is outside its batch; a failed delivery holds back the rest of its partition. `maxAttempts` 5, then `failed_at`; an `UndeliverableError` (unknown kind, bad payload) fails at once; an `OutageError` (connection refused or reset from `start()`) rolls the batch back uncounted. `enqueueSync` adds nothing while an unclaimed sync of the same mode waits. `kickRelay()` wakes the relay in-process after a commit. The relay is `src/server/plugins/relay.ts` (dev only, polls every 2 s), delivering through `relay-deliver.ts`. `pnpm sync [full|delta] [slug...]` queues syncs.
- **Ingest runs.** `ingestWorkflow(tenantId, documentId, version, outboxId | null, { fanOutPages?, rangePages? })`. A run whose version a newer sync replaced, or whose document was deleted, stops without writing. A PDF of more than 500 pages fans out to child runs of 250 pages (`ingestRangeWorkflow`, ten started at a time), each resuming the parent's hook (`defineHook`, the cookbook's child-workflow pattern). Chunk ordinals are `rangeIndex * 100000 + ordinal`, so they sort but have gaps; a single-run document's start at 0. The filing ingests as 12 children and 5,274 chunks. A document that fails is marked `failed`. Retry limits: 3 for the database steps, the parse and the subscription, 5 for downloads and the directory and drive syncs.
- **Workflow files import steps only.** The workflow bundle keeps every export of a file a workflow imports, so a helper there drags postgres into the sandbox, which the build refuses. So `sync.ts` and `ingest.ts` import only `sync-steps.ts` and `ingest-steps.ts`, which export only steps; helpers live in `sync-common.ts` and `ingest-deps.ts`.
- **Page routes.** `POST /api/ingest/rasterise?page=N` (PDF body, PNG back) and `POST /api/ingest/ocr` (PNG body, JSON back), with handlers in `src/routes/api/ingest/-pages.ts`. Both rasterising and OCR go through routes, though tesseract.js is WASM: its worker script and model are files it finds on disk, which a step bundle on Vercel may not have. Keep it there: nobody has run `ocrPng` inside a step bundle on Vercel, so wave 2 shouldn't move OCR into a step. Steps authenticate with `x-ac-internal`, an HMAC of `BETTER_AUTH_SECRET`. To load in dev and in the build, `vite.config.ts` keeps `@napi-rs/canvas` and `tesseract.js` out of the optimizer and external in server environments, and `nitro.config.ts` traces the tesseract packages into `.output` (bundled, tesseract.js read `__dirname` and the production build answered 500; the package adds about 65 MB).
- **Webhook.** The notification URL is `/api/webhooks/workspace?tenant=<tenant id>`. A notification is accepted only when its subscription id and clientState (compared by hash, in constant time) match that tenant's `sync_state`; one that matches nothing gets 403 and queues nothing. The validation token comes back as text/plain, at most 1,024 characters.
- **fake-workspace membership control** (approved by the coordinator). `POST /_control/sites/{site}/groups/{groupId}/members` with `{ member_id }`, and `DELETE .../members/{memberId}`. Behind the same dev gate, control header and Origin check as the other control routes. Users only: a subgroup follows its path (400). 409 for a user already in, 404 for one not in. The change shows in `/members` and `/transitiveMembers`, never in delta or notifications (Graph sends none for membership), and `/_control/reset` undoes it.
- **`ex smoke` "ingestion"** (check 7) compares, per tenant and as the app role, the files fake-workspace serves now with the live documents: the same set, all `ready`, each with chunks at its version and a stamped ACL; and the Heron memo's `document_acl` is `/Kestrel/Exec` only.
